## Commands

```bash
# Everything runs on PostgreSQL — there is no SQLite mode any more.
cp .env.example .env                 # then put a real SECRET_KEY in it
docker compose up --build -d         # app + db → http://localhost:5001
docker compose down

# Tests — need a Postgres; the compose file below provides one (port 55432, tmpfs)
docker compose -f docker-compose.test.yml up -d
pip install -r requirements-dev.txt
pytest                               # 814 tests
docker compose -f docker-compose.test.yml down
LOGISTAT_TEST_DATABASE_URL=postgresql+psycopg2://u:p@host:5432/db pytest   # another DB
# On .32 there is no pytest/venv — use the prebuilt runner image instead:
docker run --rm --network host -v /opt/LogiStat:/app -w /app logistat-testrunner:latest pytest -q

# Static check (npm i -g pyright; basic mode — pyrightconfig.json) — must be 0 errors (CI blocks).
# On .32 the libraries are not installed, so local pyright is laxer than CI (Optional from
# werkzeug/flask types) — CI is authoritative.
pyright

# Data consistency after every deploy (read-only; exit 1 = billing/data mismatch)
ssh testowy 'docker exec -w /app logistat-test python scripts/sprawdz_spojnosc.py'

# Local run without Docker (needs a reachable Postgres)
DATABASE_URL=postgresql+psycopg2://logistat:pass@127.0.0.1:5432/logistat \
  SECRET_KEY=$(python3 -c 'import secrets;print(secrets.token_hex(32))') python app.py

# Database reset (drops all data)
docker compose down -v && docker compose up -d      # re-creates + seeds
```

Default admin after seed: `admin` / `admin123` — override with `ADMIN_PASSWORD` **before the first start** (`docs/DEPLOY.md`). Logging in with `DEFAULT_ADMIN_PASSWORD` sets `session['wymus_zmiane_hasla']`: everything except `/profile` redirects there (API → 403 JSON) until the password is changed (checked at login, so it covers existing databases too).

## Review & CI

Every PR: **green CI** (`.github/workflows/testy.yml` — pytest on Postgres 16 + Python 3.11 like production, pyright 0 errors, `node --check static/*.js`) and a review against **`docs/REVIEW.md`** (the project's invariants as a checklist) **before** merge and deploy. A fixed bug gets a failing test first. After a deploy run `scripts/sprawdz_spojnosc.py` (`tests/test_spojnosc.py` keeps it working).

## Architecture

**Package `logistat/` (all code) + `app.py` (~30 lines, entry point)** — split from a 6 836-line `app.py` in steps 0–6, 2026-10-16…19 (history and reasons: `docs/ARCHITEKTURA.md`, „Przeglad architektury"). `app.py` = `app = create_app()`, then `init_db()` at import (every gunicorn worker; skipped with `LOGISTAT_BEZ_INIT=1` for read-only tools) — nothing else, no re-exports (removed 2026-10-20). **Tests import from the package** (`from logistat.models import ImportedCarton`, `from logistat.extensions import db`); only `conftest.py` imports `app` (after setting `DATABASE_URL`, which runs `init_db()`), and a test that needs the Flask object uses `from app import app`. **`logistat/__init__.py` imports nothing** (importing a pure module loads the package first — it must not pull Flask); `create_app()` lives in **`aplikacja.py`** (config, error handlers, `static_v`/`localdt`, `user_loader`, blueprint registration — **never touches the DB**, `test_create_app_nie_dotyka_bazy`). **`baza.py`** = `init_db()` under `pg_advisory_lock`: `create_all`, `MIGRACJE_KOLUMN` / `migrate_columns()`, one-off data migrations, seed. Import direction **web → services → models → extensions**, never back to `app` (`tests/test_logistat_moduly.py`, in subprocesses):
- **Pure logic, no Flask/SQLAlchemy:** `czas.py` (`local_today`, `local_day_bounds`, `iso_z`, `utc_to_local`), `kategorie.py` (`STAT_CATEGORIES`, labels, `liczba`, `TOTAL_AMOUNT_BEZ`), `tabela_ilosci.py`, `okresy.py` (`zlacz_okresy`, `suma_zlaczonych_okresow` — one implementation), `normy.py` (`policz_wydajnosc`).
- **`config.py`** (`resolve_secret_key`, `resolve_database_url`, defaults), **`extensions.py`** (`db = SQLAlchemy()`, `login_manager` — no app; `create_app()` calls `init_app`).
- **`models/`** by area: `uzytkownicy` (User, UserOption, `ROLES`), `zmiany` (Shift, attendance, activities, assignment, `SzkolenieCzynnosci`, DailyStat), `paczki` (ImportedCarton, UdzialPaczki), `rozliczenie` (GeneralStat, CostMapping, `rates_for`, CountryMapping, Forecast, category names), `czas_pracy` (WorkerTimeEvent, HistoriaCelu), `ustawienia` (AppSetting, `get_setting`). A new model goes into the right file **and** its import list in `models/__init__.py` (that is what `create_all()` sees). Request validation that `abort()`s or reads `current_user` (`resolve_user_option`, `ustaw_szkolenia`) stays in `app.py`.
- **Services (DB, no request):** `rozliczenie.py` (`klucz_linii`, `recompute_general_stat`, `scan_category_totals`, `scan_coverage_map`, `przenies_linie`), `paczki.py` (`przelicz_ilosci_udzialow`, `odswiez_roznice`, `zapisz_tabele_kartonu`, `bledy_paczki`), `import_paczek.py` (`importuj_wiersze(rows, data_pliku, actor_id)`, CSV/Excel cell parsing). They never read `current_user`/`request` — the author comes as a parameter; `app.process_import_rows(rows, data_pliku)` is the thin wrapper that passes `current_user.id` (tests keep calling it with `acting_admin`).
- **Routes — all of them — are blueprints in `logistat/web/<area>.py`** (step 5, 2026-10-19), endpoint names `area.function` (`url_for('paczki.paczki_view')`, `request.endpoint == 'normy.stats'`): `auth` (/, login, logout, profile, favicon; forced password change as `before_app_request`), `admin`, `imports`, `forecast`, `normy`, `dashboard`, `przydzial` (assignment + data entry), `rozliczenie` (general stats + export), `paczki`, `czas_pracy`, `stanowisko` (scanner, package times, lookups). DB-only helpers of an area live in a service module (`normy_dane`, `dashboard_dane`, `przydzial`, `czas_pracy_dane`, `rozliczenie`, `paczki`, `import_paczek`); anything that `abort()`s, reads `request`/`current_user` or builds a response stays in the blueprint. Direction **web → services → models → extensions**, never back (`tests/test_logistat_moduly.py`: services don't import `logistat.web`, nothing imports `app`).
- **Web layer `logistat/web/`:** `wspolne.py` — `leader_required` / `admin_required` (roles from `PRIVILEGED_ROLES`), `acting_as_admin`, `json_body`, `parse_date`, `parse_shift_number`, `require_int`, `bezpieczny_next`, `blad_nieznanej_paczki`. **URLs and methods are the contract** (JS, scanner stations, bookmarks): `tests/test_trasy.py` compares `app.url_map` with `tests/mapa_adresow.txt` (a new route = update the file in the same PR) and checks that every `url_for('…')` in templates/`app.py`/`logistat/` resolves, plus `login_view` and `BEZ_WYMOGU_ZMIANY_HASLA`. Renaming an endpoint to `blueprint.name` → fix all three in the same PR. The race tests patch `parse_scan_categories` in `logistat.web.stanowisko` and `stan_czasu_dzis` in `logistat.web.czas_pracy` (the module where the route looks the name up — patching where it is defined does nothing) and assert the stub was called.
- New code: pure logic → `logistat/<topic>.py`; DB access → a service or `models/`; anything with `request`/`current_user`/`abort` → the area's blueprint. Never add code to `app.py`.

**Tests:** `tests/` (pytest). `conftest.py` sets `DATABASE_URL` **before importing `app`** (it runs `init_db()` at import) → `…@127.0.0.1:55432/logistat_test`, overridable with `LOGISTAT_TEST_DATABASE_URL`; unreachable DB → import raises with the start command. Each test gets a fresh schema + seed. Coverage is concentrated on money paths (import aggregation, `recompute_general_stat`, double rate, cost math) plus permissions, day boundaries, validation, page smoke test. `IsolatedClient` clears `g._login_user` / `g._rates_cache` per request — Flask reuses the test's app context, so two clients would otherwise share the cached login.

**Database: PostgreSQL only.** `DATABASE_URL` is mandatory — `resolve_database_url()` raises at import if missing or SQLite. `.31` overrides the `db` service in `docker-compose.override.yml`. Flask-SQLAlchemy, no Flask-Migrate. **The ORM is the single source of truth for the schema** (`db.create_all()`); never reintroduce a hand-written DDL file (the old one broke `json.loads` with JSONB and wrote local time via `DEFAULT NOW()`).
- New **tables**: `db.create_all()` handles them on startup.
- New **columns**: **must** go into `MIGRACJE_KOLUMN` in `logistat/baza.py` (applied by `migrate_columns()`, `ALTER TABLE … ADD COLUMN IF NOT EXISTS`). A failing ALTER / index **aborts startup** with the column name (2026-10-16; it used to be swallowed). `create_all()` never adds a column to an existing table → `UndefinedColumn` after deploy, and ordinary tests can't see it (fresh schema). **Add a case to `tests/test_migracje.py`** with every new column.
- The `"user"` table name is a reserved word — quote it in `migrate_columns()`; unquoted, the try/except swallows the syntax error silently.
- **No `func.date()` for day grouping** — group in Python via `local_day_bounds()`.
- JSON lives in `db.Text` (JSONB is banned): `GeneralStat.category_data`, `CostMapping.rates_data`, `ImportedCarton.scan_category_data` — always via `get_…()` / `set_…()` accessors.

**Auth:** Flask-Login, `@leader_required` / `@admin_required`:
- `operator` — scanned in at shift start, no login
- `leader` — password login; scanner/assignment/data-entry/time-tracking + **CSV/Excel import** + **General Stats read-only, without costs**
- `admin` — everything + admin panel, General Stats costs/editing, country/cost mappings

`/api/users` is leader+ but only an **admin** may create/edit/deactivate `leader`/`admin` accounts, change roles or set passwords (403) — `ROLES` / `PRIVILEGED_ROLES` / `acting_as_admin()`. Degrading/deactivating the **last active admin** → 400. `login()` and `load_user()` both check `is_active_user`, so soft-delete (`DELETE /api/users/<id>`) kills live sessions. **Login limit** (2026-10-19): 5 failed attempts per login (lower-cased) in 15 min (`MAKS_PROB_LOGOWANIA`, `OKNO_PROB_LOGOWANIA` in `web/auth.py`, table `proba_logowania`, in the DB because of 2 gunicorn workers) → 429 even with the right password; success clears the counter. **API without a session → 401 JSON** (`unauthorized_handler` in `aplikacja.py`), **without the role → 403 JSON** (`_odmowa_dostepu()` in `web/wspolne.py`); pages still redirect. **Logout is POST only** (form in `base.html`).

**Sidebar** is grouped by **who operates the screen**, not by permission — the two can disagree: `Czasy paczek` sits under Pracownik but is still `@leader_required` (a station screen); don't "fix" either side: **👷 Pracownik** (Skaner zmian, Czas pracy, Czasy paczek, Paczki inspektor) · **🧑‍💼 Lider** (Dashboard, Forecast, Przydzielanie, Wpis ilości, Normy, Paczki (dane), Czasy pracowników, Import danych, Statystyki ogólne, Użytkownicy) · **🛡️ Admin** (Czynności, Panel Admina). Each group header sits **inside** the same role conditional as its items. Group headers are **bars** (`.nav-section`, `--menu-sekcja`, a translucent shade so it works on both ends of the gradient) with a divider above each group (2026-10-22). **Logwin logo** `static/img/logwin.svg` (Wikimedia Commons, `viewBox` added) sits above „LogiStat” on a **white plate** (`--logo-tlo`) in both modes — never recolour it.

**Frontend:** Vanilla HTML/JS + Jinja2, no framework, Chart.js. All templates extend `base.html`. **Page JS lives in `static/js/<page>.js`** (2026-10-16; `base.js` = shared helpers, `motyw.js` = `motyw()` in `<head>`, `tabela_ilosci.js`), included with `<script src="{{ static_v('js/…') }}">` **at the place the inline script used to be** (order matters — see the autosave gotcha). A template keeps at most a data block `const X = {{ x|tojson }};` right before its script (`tests/test_js_w_plikach.py`). Tests that check page JS use `strona_z_js(client, url)` (conftest). `test_xss.py` scans `static/js/*.js` too.
**Theme (2026-10-20, operations): light „C2” in Logwin colours** (replaced the dark graphite of 2026-10-16) — every colour is a token in `:root` of `static/style.css`: app background grey **`#DFE2DC`** (operations: clearly grey, not white), white cards, graphite text; **menu = Logwin-logo gradient** blue `#164E94` → green `#4F8F22` (`--menu-tlo`, 160°, variant B 2026-10-22; was flat green #6FA83A) with white text, active item = **white card, blue text + green bar** (`--menu-aktywna`, `--menu-aktywna-tekst`, `--menu-pasek`), section bars = `rgb(0 0 0 / .22)`; **accent = Logwin blue `#325C96`** (links, active tabs). **Buttons: outline only** — border + coloured text, no fill (`.btn` blue, `.btn-primary` thicker border, `.btn-success`/`.btn-danger` green/red outline; white outline inside the menu). Statuses in darker hues readable on white (success teal-green, warning amber, danger red, `--double-rate` orange). **No literal colours in templates/CSS**: `var(--x)`, with alpha `rgb(var(--x-rgb) / .12)`. Text on an accent/blue fill = `var(--on-accent)` (white). Chart.js → `motyw('--x')` (`static/js/motyw.js`). **Dark mode (2026-10-22):** `:root[data-motyw="ciemny"]` overrides colour tokens only (graphite palette of 2026-10-16, grey menu, green active bar); default stays light, OS preference ignored. Choice per **browser** in `localStorage['logistat-motyw']`, applied in `<head>` by `motyw.js` (try/catch); toggle = 🌙/☀️ icon in the sidebar user row (`przelaczMotyw()`), which fires `zmiana-motywu` — pages with charts redraw on it (Normy, Forecast; a new chart page must too). **Every new `:root` colour token needs its dark counterpart.** Text on an active shift tab = `var(--on-shift)`. Headings `--font-head` (Montserrat), body Inter. Mock-ups operations chose from: artifact V16e3Zme9bJbtJa4MbzZvm.

## Core data flows

- **Shift attendance:** leader scans badges → `ShiftAttendance` per `Shift`.
- **Activity assignment:** drag operators to activities → `ActivityAssignment`. `POST /api/assignment/save` **replaces the whole shift** (delete + insert), so: it locks the `Shift` row (`with_for_update()`), and `GET /api/assignment/data` returns `wersja` (`wersja_przydzialu()` — hash of the sorted `(user_id, activity_id)` pairs, no column) which the client sends back; a stale one → **409 + `konflikt: true`**, nothing overwritten (two leaders on one shift). No `wersja` in the body = old behaviour (`tests/test_przydzielanie_wersja.py`). AI suggestions save immediately too, so applying them over a non-empty board asks first.
- **Activity training (2026-10-13, operations):** `SzkolenieCzynnosci` (`szkolenie_czynnosci`, PK `(user_id, activity_id)`; row = trained). `POST /api/assignment/save` rejects a **new** pair `(user, activity)` without training → **400 + `brak_szkolenia: [{user_id, activity_id, osoba, czynnosc}]`**, nothing written; a pair **already saved** on that shift stays allowed (unticking must not block the whole shift's save — the board marks it ⚠️). Checked **before** the delete. Board: `szkolenia` in `/api/assignment/data`, a drop onto an activity without training leaves the card where it was and opens „⛔ Brak szkolenia”. AI suggestions only go to trained activities. Leader+ edits via `PUT/POST /api/users` field `czynnosci` (list of ids, replaces the set **among active activities only** — training for a disabled activity survives); Users modal (two columns, `.modal-szeroki` — one column didn't fit a laptop screen; every `.modal` scrolls inside at `max-height: 92vh`) → „✅ Przeszkolony w czynnościach”. New users and new activities start **untrained**. One-time `zaznacz_wszystkich_przeszkolonych()` in `init_db()` (marker `migracja_szkolenia_czynnosci`) ticked every existing user × activity. Tests: `make_user(..., przeszkolony=True)`; `tests/test_szkolenia_czynnosci.py`.
- **Daily stats:** leader enters quantities → `DailyStat` (audit trail).
- **Forecast:** Forecast and Actual are **pieces** (`SUM(stueckzahl)` by data pliku), never packages — labels say „sztuki”. `diff` = **Actual − Forecast** everywhere (API `/api/forecast/chart-data`, table, summary, chart, Excel „Różnica (A-F)") — minus = arrived less than planned. It was F−A until 2026-10-08 and operations read +70 000 as a surplus.
- **AI suggestions** (`/api/assignment/suggestions`): greedy, 30-day average `DailyStat.quantity` per user × activity.
- **Assignment estimate** (2026-10-13): `/api/assignment/data` → `wydajnosc` = `wydajnosc_czynnosci(shift date)` — per activity, the average **of one person, over all workers** (not only those on the shift), last `DNI_SREDNIEJ_PRZYDZIALU` (30) days: `{szt_zmiana_os, szt_h_os, zrodlo, probek}`. Board header shows `osób × average` per shift and per hour, recomputed on every drag. `CZYNNOSC_SKANOW_PACZEK` (`Post Processing`, by name) = team `srednia_szt_h` from `przeglad_zespolu()` (scans, same as Normy); every other activity = mean `DailyStat.quantity` per entry. Shift = `GODZIN_ZMIANY` 7.5 h (8 h − break). No data → no key, UI says „brak danych” (never 0). `tests/test_przydzielanie_estymacja.py`.

**Package scanning — two modules:**
- `/scan-package` („Skan paczek"): **read-only** `GET /api/package-lookup`. `scanned = processed_by OR scan_start_at`; `finished = scan_end_at`; "kto" = `processed_by_name` else `scan_start_by_name`.
- `/scan-paczki` („Czasy paczek"): tabs Start / Koniec → `POST /api/package-time/start|end` (`scan_start_at`/`scan_end_at` + `_by`). Steps: badge scan → package scan; on Koniec a third step is the **quantity table** (see below) → body `tabela` + `tryb`. Legacy body `categories` (per category → `scan_category_data`) is still accepted — a station tab opened before the deploy sends it. No quantities = time only.
  - **Quantity table (2026-10-15, operations):** rows = `GRUPY_ARTYKULOWE` (Biżuteria, Akcesoria, Okulary, Tekstylia — a constant, no admin CRUD), columns Brak / Nadwyżka / Uszkodzone / Podwójnie / Potrójnie + `DODATKI_TABELI` (sortowanie inne, 2× podmiana karty, worki). Import has **one** quantity per carton → **Ilość Biżuterii = `stueckzahl` − other groups' Ilość** (operator types those); Pojedynczo = Ilość − Brak + Nadwyżka − Uszkodzone − Podwójnie − Potrójnie. **The server computes** (`normalizuj_tabele()`): negative Pojedynczo / others > `stueckzahl` / value ≥ `ILOSC_WYGLADA_NA_KOD` → 400, nothing saved. Full table on `ImportedCarton.tabela_ilosci`; billing columns derived by **`kategorie_z_tabeli()`** into `scan_category_data` (rest of the billing path unchanged): Labelling one/twice/triple = **Biżuteria only**, twice **× 1.5**, triple **× 2** (LOGIKA_KLEJENIA.xlsx: 1st label 1, each next 0.5); Akcesoria/Okulary/Tekstylia → `accessoire`/`sunglasses`/`textile` = all pieces minus damaged; Sorting = all Uszkodzone + sortowanie inne; Card facture = both card swaps; polybag = worki. Brak bills nothing. **Halves are real** — `liczba()` everywhere, never `int()` on billing amounts. `ZRODLO_KATEGORII` (tooltips) must match `kategorie_z_tabeli()`. Shared JS `static/js/tabela_ilosci.js` (station + leader modal); fields empty, no „0" placeholder. `tests/test_tabela_ilosci.py`.
  - **Two modes:** `wzor` (no `udzial_paczki` rows) and `zespol` (any rows, and always on „Paczka do dokończenia") — each person types Pojedynczo/Podwójnie/Potrójnie/Uszkodzone **directly**, carton table = `suma_tabel()` of the rows. The station sends the mode it opened with; server expects `carton.tryb_tabeli()` → mismatch **409 `zmiana_trybu`** (someone joined meanwhile).
  - No surplus question and no „Poinformuj lidera" any more (removed 2026-10-15) — surplus is a normal entry; the leader sees ❗.
  - **❗ (`ImportedCarton.roznica`, Boolean, `odswiez_roznice()`, only finished cartons with a table):** any Brak / Nadwyżka / Uszkodzone, or in `zespol` entered pieces ≠ `stueckzahl`. Reasons `powody_roznicy()` computed live. Leader `POST /api/packages/<id>/potwierdz-roznice` („✔ Potwierdź" on `/paczki`) sets `roznica_potwierdzona_at/_przez`; a leader save via „✎ Ilości" also confirms. Dashboard „Dziś" tile „❗ Do potwierdzenia" = `do_potwierdzenia` count → `/paczki?do_potwierdzenia=1` (same set as the count).
  - Screen is enlarged with `.stanowisko-skanu { zoom: 1.27 }` (operators: text too small). Modals sit **outside** that wrapper (zoom on an ancestor breaks `position: fixed`) and carry their own large sizes.
  - **Ownership lock:** in-progress package belongs to its starter — other worker start → 409, end → 403; same worker re-start keeps the original timestamp. Finished → re-start/re-end 409.
  - Start/end read the carton **`with_for_update()`** (double Enter / two stations raced; `tests/test_skan_paczek_stanowisko.py`).
  - **Station guards:** step 1 validates the badge at once via `GET /api/employee-lookup`. A badge scanned into the package field → **400 + `kod_pracownika: true`** (`blad_nieznanej_paczki()`, checked only after the carton misses) from lookup/start/end; UI keeps step 1. JS in-flight guard per tab (`zajete`) + disabled field during a request; open quantity panel shows „Paczka NIE jest jeszcze zakończona" and confirms tab switch / leave; quantity ≥ `ILOSC_WYGLADA_NA_KOD` (100 000) refused client-side.
- **Unlock:** `POST /api/packages/<id>/unlock-scan` (leader+, „🔓 Odblokuj") clears `scan_start_at`/`_by` **and open team participations**. Finished → 409, unstarted → 400.
- **Multi-person packages (2026-10-13)** — table `UdzialPaczki` (`udzial_paczki`), rows **only when 2+ people** work a package; a single-person carton has none and is read from its own fields (no migration of old cartons). Carton = aggregate: `scan_category_data` = **sum of all rows' `ilosci`** (`przelicz_ilosci_udzialow()`, from the sum, never delta → billing unchanged); `scan_end_*` only when no open row is left (`zamknij_paczke_wielu_osob()` also sets start to the first row). `tests/test_paczka_wielu_osob.py`.
  - **📤 Paczka do dokończenia** (tab `dok`, `POST /api/package-time/przekaz`): closes the holder's row with quantities and **clears `scan_start_*`** → `do_dokonczenia()` (no start, no end, has rows). Next person: normal Start + End (End creates their row from `scan_start_at`). Others still open in a team → 409.
  - **👥 Pakowanie zespołowe** (tab `zespol`, `POST /api/package-time/dolacz`): joins a **started** package; the first join also creates the starter's row from `scan_start_at`. End: anyone with an open row (else 403); `zamknij_wszystkich` closes the rest **without quantities** (`zamkniete_przez`); leader `POST /api/packages/<id>/zamknij-zespol` („🔒 Zamknij paczkę" on `/paczki`) does the same. Normal Start by another person stays 409.
  - Station: End panel shows **only who else is working**, never their quantities (operations 2026-10-15: each declares their own part, the leader checks the ❗); with others open asks „tylko mój udział" (focus) / „dla wszystkich".
  - `processing_seconds()` = union of closed rows (no overnight gap). Coverage `scan_coverage_map()` counts only **finished** cartons (a handed-off part already has quantities).

- **Barcode scanner:** EAN-128 via USB HID, 300 ms keystroke buffer (raise to 500 ms if slow).
- **Drag & drop:** native HTML5, click multi-select, drag moves all selected.
- **User options:** `User.worker_type_id` („Rodzaj pracownika") and `User.shift_group_id` („Nazwa zmiany") → `UserOption(kind, name)`, `USER_OPTION_KINDS`. - **Logging:** `logging.getLogger(__name__)` (logger `logistat.*`, configured in `create_app()` → stderr → `docker logs`), never `print()`. Seed lines start with `[SEED]` (`test_init_race` checks them).
- **Excel exports** use `logistat/web/excel.py` (`odpowiedz_xlsx`, `styl_naglowka`, `RAMKA`); colours stay per export.
- **Remote work on .32 (2026-10-12):** Claude Code runs as a Remote Control session inside tmux session **`claude`** (`tmux new -d -s claude -c /opt/LogiStat 'claude --remote-control logistat'`), used from claude.ai/code. Check `tmux ls` before starting anything: **never start a second Claude session** next to it (it would just eat the server's resources), and never kill `claude` or the other tmux sessions (`gemini`, `linux`, `postgres`). It doesn't survive a reboot, so start it again with the same command.
- **Config** (`docs/DEPLOY.md`): `SECRET_KEY` mandatory — `resolve_secret_key()` raises (bypass `LOGISTAT_ALLOW_DEV_SECRET=1`); from `.env` via Compose. **Never `${VAR:?}` in `docker-compose.yml`** — resolved before the override merges, breaks `.31` (no `.env`). `MAX_UPLOAD_MB` (32) → 413 JSON. `SESSION_COOKIE_SAMESITE=Lax` always; `SESSION_COOKIE_SECURE` opt-in (`.31` also on plain HTTP).
- **Login `?next=`** only via `bezpieczny_next()` (a local path; full URLs, `//host`, `\` → index — open redirect).
- **JSON into `<script>`:** `const x = {{ v | tojson }};` — never `JSON.parse('{{ v|tojson|safe }}')` (a `"` or `\` in an admin-edited category name broke the page).
- **`/api/` errors are JSON** (one `@app.errorhandler(HTTPException)`): `abort(400, 'komunikat')`, front reads `data.error`. Helpers: `json_body()`, `parse_date()` (empty → today; for range filters call conditionally), `parse_shift_number()`, `require_int()`.
- **Static:** `{{ static_v('style.css') }}` appends mtime.
- **JSON in an HTML attribute → single quotes:** `data-x='{{ v | tojson }}'`. `tojson` escapes `'` but not `"`, so a double-quoted attribute is cut at the first `"` — the `/paczki` „✎ Ilości" modal showed all zeros and saving would have wiped the quantities (fixed 2026-10-13). CSS variable is `--bg-card-solid`; `--surface` does not exist (transparent modals) — check new `var(--x)` names against `:root`.
- **`escapeHtml()` (`static/js/base.js`)** on everything from the DB going into `innerHTML` — barcodes come from imports, risk is *stored* XSS.
- **Autosave, no „Zapisz" button** on the bulk screens — Przydzielanie, Wpis ilości, Forecast, Statystyki ogólne (people forgot the button and lost work). One helper in `static/js/base.js`: `autoZapis.zaplanuj(klucz, wyslij, pola)` + `zapiszJson()`. Rules: wire fields with **`autoZapis.poWpisaniu(pole, zapisz)`** — saves **1.2 s after typing stops** *or* on `change` (blur), same value never twice; a field waiting for its pause counts as unsaved (`beforeunload`, „✎ Zapis za chwilę…"), and `przedOpuszczeniem()` pushes it out first — closing a tab with the cursor in a field fires no `change`, so blur-only lost the last number silently. Build the payload (incl. date/shift) **at change time** — pages keep `loadedDate`, not the date field's live value; **one request in flight per key**, then only the newest pending one (key = row / shift); status in `#autoZapisStatus` (Zapisywanie / ✓ Zapisano / ⚠ + Ponów or the error's `akcja`); `beforeunload` armed only while pending/failed; **`await autoZapis.przedOpuszczeniem()` before** shift/date switch, reload, filter submit and export links. `zapiszJson()` treats a non-JSON or redirected response as failure — an expired session redirects to `/login` with **200**. Per-row saves only: forecast saves one day (`saved === 1`), daily stats one `(user, activity)`, general stats one line (`gs:<id>:main|dr`, amount fields only — the readonly cost field also has `inline-input`; no amount fields → send nothing, an empty dict would wipe the line's categories). Other endpoints unchanged (assignment: see Core data flows). **Gotcha:** some pages (e.g. `general_stats.html`) put their `<script src>` in `{% block content %}`, which runs **before** `base.js` — call `autoZapis`/`zapiszJson` there only from events or `DOMContentLoaded`, or the page gets a `ReferenceError` and silently stops saving.
- **Explicit-save forms stay explicit** (modals, `/admin/settings`, stats target, **cost mapping** — billing, and „copy previous month" is deliberate). Cost mapping shows „● Niezapisane zmiany stawek", arms `beforeunload` and asks before loading another month while rates differ from the loaded ones. **Save and „copy previous month" use the *loaded* month (`loadedYear`/`loadedMonth`), never the live selects** — switching the month list without „Pokaż stawki" used to save the old month's rates under the new one; the button shows which month it writes. Modals with fields carry **`data-modal-guard`**: a backdrop click with changed fields asks first (it used to discard silently); „Anuluj" does not ask. New modal with a form → add the attribute.
- **Shift colours:** `--shift-1` (blue) / `--shift-2` (orange) in `:root`, applied by `data-shift="1|2"` on `.shift-tab.active`, `.shift-badge`, `.shift-frame` (working area of the edited shift), `.shift-card` (dashboard), `.scanner-shift-badge` / `.scanner-page`.
